# 产品范围与迁移顺序

日期：2026-07-20

## 定位

DANMU 不是普通弹幕查看器，而是面向知识型主播的弹幕与直播监控工作台。核心结果是降低漏看重要互动的概率、保护直播节奏，并让重点互动可以被复用。

## 迁移顺序

1. 建立平台无关的 `DanmuCore`，先固定标准事件模型和会话规则。
2. 从直播助手迁入 B 站连接与命令解析，作为首个平台 Adapter。
3. 实现独立弹幕窗、置顶、自动跟随、分类和关键词过滤。
4. 在 `BilibiliDanmu` 内增加可选账号授权与主动发弹幕，不改变公开监看的免登录边界。
5. 增加本地弹幕会话持久化、搜索和导出。
6. 增加固定样式的轻量直播输出，解除重点上屏对完整画布的依赖。
7. 完成真实 B 站直播、断线重连和 OBS Browser Source 验收。

当前 vNext 已完成第 5 步的 JSONL 会话归档、异常恢复、全局搜索和 Markdown/JSON 导出。第 6、7 步中的 OBS Browser Source 仍留在后续版本，不以现有独立展示窗冒充验收完成。

## 不直接复制的实现

- 直播助手的全局 `AppStore`。
- 画布项目、Widget、草稿和发布态。
- React/Moveable 编辑器和素材管理。
- 播放器、音频混音台和完整 OBS 配置；只保留独立 Adapter 提供的状态、OBS 现有场景读取/切换、指定麦克风、单路麦克风电平监看和推流启停遥控。

迁移时以领域行为为准，逐个重建到新的 Module；不复制整个目录后再删除无关功能。

## 首个可用版本门禁

- 输入公开房间号后可以稳定接收事件。
- 连接成功后先补齐公开接口返回的最近历史弹幕，再持续接收实时事件。
- 断线能够自动恢复，并明确展示连接状态。
- 手动回看不会被新弹幕立即拉走，自动跟随能够恢复。
- 独立弹幕窗可实时调节字体大小与窗口不透明度，并支持原生弹幕和聊天气泡两种显示方式。
- 关注、分享、PK、抽奖/红包、房管/禁言、开播/下播和平台通知必须转换为标准平台事件；主窗口与独立窗可按重点、社区和房间分类筛选。
- 页面顶部固定两行：第一行左侧依次显示闪烁 LIVE 与直播间标题，右侧显示依据 `live_time` 计算的已开播时长；第二行显示主播名称、无背景 OBS 连接符号（绿色 `<->` / 红色 `<-x->`）和无背景红色 MIC 状态（`◉` 开启 / `○` 未开启），不显示直播分区。OMP Box 输入框上边框左侧发送指示无背景且两侧各留一个空格；右侧只用 ◉、♥、▤、● 四种符号标识累计看过、累计点赞、本次弹幕和当前在线，不出现中文标签。主播自己的弹幕在粉色名称前显示 `♚`。
- 数据口径固定为：`getRoomBaseInfo.live_time`=中国标准时间的本次开播时刻，`live_status` 的 0/1/2=未开播/直播/轮播，`WATCHED_CHANGE.data.num`=累计看过，`LIKE_INFO_V3_UPDATE.data.click_count`=累计点赞，`getOnlineRank.data.onlineNum`=登录态下的当前在线人数。`getRoomBaseInfo.online` 与 WebSocket 心跳 op=3 都是人气值，不得显示成人数；未登录或在线接口失败时显示 `--`，Adapter 对未知状态或字段漂移显式报错。
- 重点上屏不依赖完整直播画布。
- GUI 与 TUI 的有限 OBS 遥控保持同一用户可见契约，由各自平台 Adapter 实现；停播必须二次确认，且不联动录制、Replay Buffer 或弹幕会话。
- 公开监看不需登录；未授权时主动发弹幕会在本地被拒绝。
- 登录态界面必须提供账号管理和退出登录；已登录状态下不得继续显示“登录后可发送”的占位提示。
- 主动发弹幕的前端与 Adapter 共同执行 22 字符上限；发送状态以主播身份和弹幕内容的直播间回流匹配为准，不以 HTTP 接口接受请求作为最终成功。主播身份优先使用用户 ID，事件缺少 ID 时回退到完整昵称。
- 主动发送后只更新发送区状态，不向消息流插入本地气泡；只有真实回流事件才进入消息列表并使用主播专属颜色，超时或请求失败显示失败状态。
- Dock reopen 必须恢复主窗口，菜单栏提供常驻入口和核心窗口动作。
- Cookie、CSRF 和其他账号敏感字段只存在于 B 站 Adapter 的本机私有存储，不进入领域层、日志和导出。
- 一场真实直播结束后可以搜索当前及历史记录，并导出可重建的 Markdown 复盘与 JSON 快照。
