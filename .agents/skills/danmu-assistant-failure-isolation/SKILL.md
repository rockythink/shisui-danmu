# DANMU 助手故障隔离检查表

## 目标

修复助手异常时，避免把局部模型输出错误升级为整个 TUI 停机，同时保证真实连接、身份、协议和存储故障不会被错误吞掉。

## 分类一：候选目标非法

检查候选是否只引用当前批次消息 ID，并确保每个目标最多出现一次。不要把观众 UID、历史 ID 或其他批次 ID 当作当前目标。

出现未知或重复目标时：

1. 整批拒绝，不发送部分合法候选；
2. 不重试该批旧消息；
3. 保留此前待审候选及当前授权；
4. 继续接受后续新问题；
5. 日志分别标记未知或重复，并记录轮次和具体错误 ID；
6. 不停止整个助手。

回归应至少覆盖：未知目标后正常批次、重复目标后正常批次、错误批次零发送、已有待审候选和授权未被篡改。

## 分类二：身份或授权失效

身份校验或授权保存失败时：

1. 保留原始错误消息；
2. 暂停助手并撤销发送权限与自动恢复状态；
3. 保留房间、会话、手工草稿和输入能力；
4. 不绕过身份检查；
5. 要求用户检查或重新登录 AI 发送账号，并显式重新授权。

只在命令的操作阶段局部处理该错误。成功操作后的 journal snapshot 或其他磁盘错误仍须传播。测试应覆盖直接命令、命令搜索、Unicode 草稿和真实本地传输路径。

## 分类三：真实基础设施故障

连接断开、身份协议不一致、协议损坏、当前数据库损坏、磁盘满等不能被归类为普通模型输出错误。按照安全策略停止或报错，不得假报成功。

## 验证策略

- 先用确定性本地模型服务复现错误序列。
- 验证旧版确实失败、新版不重启即可处理下一条正常输入。
- 不向 B 站发送测试消息，除非当前任务明确授权。
- 完成后执行仓库完整 verify、安装 Release，并核对安装文件哈希。
- 报告中明确：修复的是隔离和恢复，不是保证模型永远输出合法 ID。
